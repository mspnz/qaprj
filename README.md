# OpenCode QA Multi-Agent System

Мультиагентная QA-система для автоматизации сквозного цикла обеспечения качества: от извлечения требований из Confluence до синхронизации задач в Jira и создания тестовой модели в TMS Qase.

---

## Архитектура системы

В проекте используется ролевая модель оркестрации (`primary` + `subagents`). Обмен контекстом между этапами происходит исключительно через валидированные JSON-артефакты (паттерн **State Isolation**).

```text
                      ┌──────────────────────┐
                      │  orchestrator-agent  │ (primary)
                      └──────────┬───────────┘
         ┌───────────────────────┼───────────────────────┐
         ▼                       ▼                       ▼
┌──────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│requirement-review│    │   task-design   │    │   test-design   │
│      -agent      │    │     -agent      │    │     -agent      │
└────────┬─────────┘    └────────┬────────┘    └────────┬────────┘
         │                       │                       │
     Confluence                 Jira                   Qase
```

### Агенты (`.opencode/agents/`)
* **`orchestrator-agent`** (`mode: primary`): точка входа. Инициализирует запуск, координирует сабагентов, проверяет артефакты на **Quality Gates (QG-1..QG-4)**, инициирует циклы **Self-Refine** (до 2 итераций), контролирует экспорт и формирует итоговый отчет.
* **`requirement-review-agent`** (`mode: subagent`): читает требования из Confluence (Read-only), отсекает шум и выявляет дефекты (`ambiguities`, `contradictions`, `missing_info`).
* **`task-design-agent`** (`mode: subagent`): проверяет дубликаты в Jira, декомпозирует подтвержденные требования на задачи разработки и выполняет их экспорт.
* **`test-design-agent`** (`mode: subagent`): проектирует структуру разделов (`suites`) и тестовые сценарии (`positive`, `negative`, `boundary`) с учетом рисков, после чего экспортирует их в Qase.

### Навыки (`.opencode/skills/`)
Чистая методология анализа и строгие контракты данных:
* `requirement-review` — правила ревью, классификация рисков и разметка статусов (`confirmed` / `blocked`).
* `task-design` — декомпозиция, формулирование критериев приемки (AC) и расчет покрытия.
* `test-design` — техники тест-дизайна, определение приоритетов и построение матрицы покрытия (`coverage_matrix`).

## Структура артефактов

Каждый запуск изолируется по ID страницы Confluence и временной метке:
`./artifacts/<confluence_page_id>/<YYYY-MM-DD_HH-mm>/`

```text
artifacts/<confluence_page_id>/<run_timestamp>/
├── requirement-review-artifact.json  # Выделенные требования, дефекты и риски
├── jira-tasks-artifact.json          # Задачи на разработку и привязка к Jira Issue Key
├── qase-test-model-artifact.json     # Тест-кейсы и привязка к Qase ID
└── final-qa-report.md                # Финальный Markdown-отчет с матрицей трассируемости
```

> **Важно:** Каждый JSON содержит блок `metadata` (`confluence_page_id`, `run_timestamp`, ключ целевого проекта), который валидируется оркестратором на каждом Quality Gate для исключения рассинхрона данных.

## Quality Gates & Защитные механизмы

1. **Защита от додумывания:** Ни один агент не имеет права генерировать требования, критерии приемки или ожидаемые результаты, если они отсутствуют в Confluence.
2. **Изоляция заблокированных требований:** Требования со статусом `blocked` (наличие блокеров/противоречий) исключаются из декомпозиции задач и тест-дизайна и выносятся в блок открытых вопросов (`question_to_owner`).
3. **Безопасный экспорт (Two-phase Commit):** Создание тикетов в Jira и тест-кейсов в Qase запускается **только после** прохождения валидации артефактов на Quality Gate (исключает попадание мусора в рабочие трекеры при ошибках генерации).
4. **Self-Refine & Retry:** До 3 повторов при сбоях сети/API внешних систем; до 2 циклов исправления артефакта через сабагента при непрохождении Quality Gate.

## Запуск

Запустите оркестратора через OpenCode CLI, передав контекст задачи:

```bash
opencode run orchestrator-agent "Проанализируй требования со страницы Confluence 12345678. Проект Jira: BILL, проект Qase: BILLING."
```
