# OpenCode QA Multi-Agent System

Мультиагентная QA-система для автоматизации сквозного цикла обеспечения качества: от извлечения требований из Confluence до синхронизации задач в Jira и создания тестовой модели в TMS Qase.

---

## Архитектура системы

В проекте используется ролевая модель оркестрации (`primary` + `subagents`). Обмен контекстом между этапами происходит исключительно через валидированные JSON-артефакты (паттерн **State Isolation**).

```text
                      ┌──────────────────────┐
                      │  orchestrator-agent  │ (primary)
                      └──────────┬───────────┘
         ┌───────────────────────┼───────────────────────┐
         ▼                       ▼                       ▼
┌──────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│requirement-review│    │   task-design   │    │   test-design   │
│      -agent      │    │     -agent      │    │     -agent      │
└────────┬─────────┘    └────────┬────────┘    └────────┬────────┘
         │                       │                       │
     Confluence                 Jira                   Qase
```

### Агенты (`.opencode/agents/`)
* **`orchestrator-agent`** (`mode: primary`): точка входа. Инициализирует запуск, определяет целевые ключи проектов (формируя новые ключи при повторном анализе той же страницы требований), координирует сабагентов, запускает программную проверку артефактов (`.opencode/scripts/validate_artifacts.py`) на **Quality Gates (QG-1..QG-4)**, инициирует циклы **Self-Refine** (до 2 итераций), контролирует экспорт и формирует итоговый отчет.
* **`requirement-review-agent`** (`mode: subagent`): читает требования из Confluence (Read-only), отсекает шум и выявляет дефекты (`ambiguities`, `contradictions`, `missing_info`).
* **`task-design-agent`** (`mode: subagent`): проверяет наличие целевого проекта и дубликатов задач в Jira, декомпозирует подтвержденные требования на задачи разработки, создает новый проект в Jira (если он еще не существует) и выполняет безопасный экспорт задач.
* **`test-design-agent`** (`mode: subagent`): проверяет наличие целевого проекта в Qase, проектирует структуру разделов (`suites`) и тестовые сценарии (`positive`, `negative`, `boundary`) с учетом рисков, создает новый проект в Qase (если он еще не существует) и выполняет безопасный экспорт тестовой модели.

### Навыки (`.opencode/skills/`), JSON-схемы (`.opencode/schemas/`) и Валидатор (`.opencode/scripts/`)
Чистая методология анализа и строгие контракты данных:
* `requirement-review` (`.opencode/schemas/requirement-review.schema.json`) — правила ревью, классификация рисков и разметка статусов (`confirmed` / `blocked`).
* `task-design` (`.opencode/schemas/jira-tasks.schema.json`) — декомпозиция, формулирование критериев приемки (AC) и расчет покрытия.
* `test-design` (`.opencode/schemas/qase-test-model.schema.json`) — техники тест-дизайна, определение приоритетов и построение матрицы покрытия (`coverage_matrix`).
* `.opencode/scripts/validate_artifacts.py` — CLI-скрипт программной валидации JSON-схем, идентификаторов, статусов и межартефактной согласованности.

## Структура артефактов

Каждый запуск изолируется по ID страницы Confluence и временной метке:
`./artifacts/<confluence_page_id>/<YYYY-MM-DD_HH-mm>/`

```text
artifacts/<confluence_page_id>/<run_timestamp>/
├── requirement-review-artifact.json  # Выделенные требования, дефекты и риски
├── jira-tasks-artifact.json          # Задачи на разработку и привязка к Jira Issue Key
├── qase-test-model-artifact.json     # Тест-кейсы и привязка к Qase ID
└── final-qa-report.md                # Финальный Markdown-отчет с матрицей трассируемости
```

> **Важно:** Каждый JSON содержит блок `metadata` (`confluence_page_id`, `run_timestamp`, ключ целевого проекта), который программно валидируется оркестратором через `.opencode/scripts/validate_artifacts.py` на каждом Quality Gate для исключения рассинхрона данных.

## Quality Gates & Защитные механизмы

1. **Защита от додумывания:** Ни один агент не имеет права генерировать требования, критерии приемки или ожидаемые результаты, если они отсутствуют в Confluence.
2. **Изоляция заблокированных требований и статус `PARTIAL`:** Требования со статусом `blocked` (наличие блокеров, противоречий или вопросов, требующих уточнения у владельца `question_to_owner`) исключаются из декомпозиции задач в Jira и тест-дизайна в Qase и выносятся в блок открытых вопросов (`question_to_owner`). Если по каким-то требованиям не были созданы сущности, они явно перечисляются в `final-qa-report.md`, а завершенному процессу с непокрытыми требованиями присваивается статус `PARTIAL` (при 100% покрытии всех требований — `COMPLETED`).
3. **Программная валидация (`.opencode/scripts/validate_artifacts.py`) и безопасный экспорт (Two-phase Commit):** На каждом Quality Gate (`qg1`, `qg2-design`, `qg2-export`, `qg3-design`, `qg3-export`) скрипт проверяет JSON-схемы из `.opencode/schemas/`, обязательные поля, допустимые статусы, форматы ID и межартефактную согласованность. Создание проектов/тикетов в Jira и проектов/тест-кейсов в Qase запускается **только после** прохождения программной валидации Design Check.
4. **Безопасный повтор (Idempotent Retry) & Self-Refine:** До 3 повторов при сбоях сети/API внешних систем с обязательной проверкой уже существующих сущностей в Jira и Qase перед каждой повторной попыткой создания (исключает дублирование проектов, задач, разделов и тест-кейсов при потере ответа от сервера); до 2 циклов исправления артефакта через сабагента при непрохождении Quality Gate.
5. **Автоматическое создание новых проектов при повторных прогонах:** Если анализ по одной и той же странице требований запускается повторно, система автоматически формирует новые уникальные ключи (`jira_project_key` и `qase_project_code` с номером итерации) и создает под них новые проекты в Jira и Qase.

## Запуск

Запустите полный сквозной пайплайн через OpenCode CLI, передав ID страницы Confluence (базовые ключи проектов `JIRA_PROJECT_KEY` и `QASE_PROJECT_CODE` подтягиваются автоматически из `.env` / `opencode.json`, а при повторных прогонах той же страницы создаются новые проекты с суффиксом запуска):

```bash
opencode run orchestrator-agent "Проанализируй требования со страницы Confluence 123456789"
```
